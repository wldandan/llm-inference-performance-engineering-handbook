# 《LLM 推理性能优化实战》教材插图设计规范 V2.0

## 1. 设计目标

本规范用于统一全书所有插图的视觉风格、信息层次、编号方式和制作流程。

设计原则：

-   一图一核心观点
-   图文一一对应
-   从概念 → 原理 → 工程 → 性能 → 优化逐步展开
-   全书使用统一视觉语言
-   每张图都可独立用于 PPT、培训和教材

------------------------------------------------------------------------

# 2. 制图流程（新增）

任何一张图都必须经过四个阶段：

    需求分析
        ↓
    Wireframe（线框图）
        ↓
    Storyboard（PPT版式）
        ↓
    Final Artwork（最终信息图）

禁止直接生成最终图片。

------------------------------------------------------------------------

# 3. 信息层次

采用四层信息结构：

Level 1：标题（回答"这张图讲什么"）

Level 2：主流程（回答"发生了什么"）

Level 3：关键说明（回答"为什么"）

Level 4：Key Takeaway（回答"应该记住什么"）

------------------------------------------------------------------------

# 4. 页面模板（新增）

统一采用四区域布局：

    ┌────────────────────────────────────┐
    │ 图号 + 标题                        │
    ├────────────────────────────────────┤
    │ 主信息图                           │
    │                                    │
    │ （流程 / 架构 / 生命周期）          │
    ├────────────────────────────────────┤
    │ 关键说明                           │
    ├────────────────────────────────────┤
    │ Key Takeaway                       │
    └────────────────────────────────────┘

禁止在一张图中放多个独立主题。

------------------------------------------------------------------------

# 5. 配色规范

  类型         颜色   用途
  ------------ ------ ---------------------------
  Compute      蓝色   算力、Kernel、Tensor Core
  Memory       绿色   KV Cache、HBM、Memory
  Scheduling   橙色   Queue、Batch、Scheduler
  Serving      紫色   Runtime、Serving Engine
  System       灰色   GPU、CPU、PCIe、Storage

颜色在全书保持一致。

------------------------------------------------------------------------

# 6. 图标规范（新增）

统一使用同一套图标：

-   👤 User
-   🌐 API
-   📦 Queue
-   ⚙ Scheduler
-   🧠 LLM
-   💾 KV Cache
-   🎯 Sampling
-   🖥 GPU
-   ⚡ Tensor Core
-   📈 Metrics

不混用不同风格图标。

------------------------------------------------------------------------

# 7. 字体规范（新增）

标题：28\~32 pt

二级标题：20\~24 pt

正文：16\~18 pt

注释：12\~14 pt

所有图片保持一致字号。

------------------------------------------------------------------------

# 8. 箭头规范（新增）

实线：

表示数据流

虚线：

表示依赖关系

回环箭头：

表示 Decode Loop

双向箭头：

表示共享

------------------------------------------------------------------------

# 9. Key Takeaway 规范（新增）

每张图底部必须有一句总结。

例如：

图1-4：

> Prefill 是 Compute Bound，主要决定 TTFT。

图1-5：

> Decode 是 Memory Bound，主要决定 ITL。

图1-6：

> KV Cache 是连接 Prefill 与 Decode 的核心状态。

------------------------------------------------------------------------
