# Chapter Review

## 总体评价

第一章《LLM 推理流程》已按课程大纲边界收紧：本章定位为“生命周期认知 + 阶段定位 + 跑通真实 vLLM 请求”，不承担第 2 章的系统指标实验任务。

正文覆盖大纲要求的 Transformer 推理流程、Token 生成过程、Prefill 与 Decode、GPU 生命周期、KV Cache 生命周期、Compute Bound vs Memory Bound。Demo 也与大纲一致，使用 Qwen/Qwen2.5-0.5B 和 vLLM OpenAI-compatible 服务观察一次真实流式请求。

## 结构问题

1. `本章导读` 已将第五个问题调整为“看到一个性能现象时，应该先定位到哪个阶段？”，避免把第 1 章过早拉入指标章节。

2. `1.1 从“用户觉得慢”开始` 保留以下顺序：

```text
先描述现象
  -> 再定位阶段
  -> 再选择指标
  -> 再判断瓶颈
  -> 最后选择优化手段
```

这个顺序符合第 1 章目标。第 1 章先建立阶段地图，第 2 章再系统定义指标。

3. `1.7` 已调整为“阶段定位中的三个线索：TTFT、ITL、TPS”，把指标降级为定位线索，避免与第 2 章重复。

4. `1.9 本章实验` 已保持单一目标：启动 vLLM 服务、发送一次真实流式请求、观察请求生命周期。不做多组变量对比，不输出 benchmark 结论。

5. `课后练习` 和 `自检清单` 已移除“三组实验”“指标变化”“性能分析结论”等越界要求，改为标注 prompt、首个 chunk、后续 chunk、usage 与生命周期阶段。

## 技术与术语问题

1. Prefill、Decode、KV Cache、TTFT、ITL、TPS 的解释前后一致。

2. `1.4 Prefill` 中关于 compute bound 的表述保留了“通常”和“不是铁律”，没有写成绝对结论。

3. `1.5 Decode` 中关于 batch 的检查项已弱化为“调度和 batching 是否影响 Decode 节奏”，避免提前进入 batch size 调参。

4. `1.6 KV Cache` 的显存直觉公式已补充 block size、对齐、分页管理和运行时预留显存等实现差异，避免被误解为精确容量公式。

5. `1.9.1 启动 vLLM 服务` 明确模型下载和环境准备由读者或实验环境提前完成，第一章不提供下载模型脚本。
